# Codebase map — full-stack-fastapi-template
Commit: aabb90126964a164e02aff39e7c385bb0598236d · Inventory: 0ff105636fd10fe964253c3aba130379e186d2ba27f11444b8060d36ffc3f5e5 · Generated: 2026-11-08

## Overview
A full-stack web application template: a FastAPI backend serving a versioned REST API, a React single-page
frontend, and PostgreSQL, run together with Docker Compose. Users sign up, log in, manage their profile and
CRUD "items"; superusers manage users. It is a monorepo of three packages (`backend/`, `frontend/`,
`packages/react-email/`) plus root tooling (`pyproject.toml`, `package.json` workspace). Size: ~2.9k lines of
Python and ~11k lines of TypeScript (much of it a generated API client). Frameworks: FastAPI with Pydantic and
SQLModel on the backend; React with TanStack Router/Query and Tailwind on the frontend.

## Components and services
- **backend** (`backend/`): FastAPI app, entry `backend/app/main.py`; routers mounted in `backend/app/api/main.py`
  (`login`, `users`, `utils`, `items`; `private` only when the environment is development, `backend/app/api/routes/private.py`).
  Talks to `db` over SQL via SQLModel; sends email over SMTP. Startup script `backend/scripts/prestart.sh` waits for the
  database, runs migrations and seeds the first superuser (`backend/app/initial_data.py`).
- **frontend** (`frontend/`): React SPA built with Vite (`frontend/vite.config.ts`), routes in `frontend/src/routes/`,
  API calls through a client generated from the backend's OpenAPI schema (`frontend/src/client/`).
- **packages/react-email** (`packages/react-email/`): email templates authored in React Email and compiled to the
  HTML templates the backend sends (`backend/app/email-templates/`).
- Compose services (`compose.yml`): **proxy** (Traefik reverse proxy routing by host name), **db** (PostgreSQL 18 with a
  healthcheck), **backend**, **adminer** (database admin UI), and for local development and tests (`compose.override.yml`)
  **mailpit** (catches outgoing email) and **playwright** (runs end-to-end tests, `frontend/Dockerfile.playwright`).
- Communication: browser → Traefik → backend over HTTP/JSON; backend → PostgreSQL; backend → SMTP (mailpit locally).
  No queues or background workers.

## Data stores and schema
- **PostgreSQL** is the only data store (`compose.yml` `db` service, `postgres:18` image; driver psycopg via SQLModel).
  No cache, queue or object store.
- ORM: **SQLModel** (SQLAlchemy 2 + Pydantic). Tables `User` and `Item` with UUID primary keys and cascade delete from
  user to items, defined in `backend/app/models.py`; data access helpers in `backend/app/crud.py`; engine and initial
  data in `backend/app/core/db.py`.
- Migrations: **Alembic** (`backend/alembic.ini`, `backend/app/alembic/env.py`), five versions in
  `backend/app/alembic/versions/`, including a data migration that replaced integer ids with UUIDs. Migrations are applied
  by `backend/scripts/prestart.sh` before the app starts, in every environment and in CI.

## APIs and integrations
- REST API under a version prefix, defined code-first in FastAPI; OpenAPI served by the app (`backend/app/main.py`) with
  operation ids customised for client generation.
- The TypeScript client in `frontend/src/client/` is generated from that schema (`scripts/generate-client.sh`,
  `frontend/openapi-ts.config.ts`) and regenerated by a pre-commit hook (`.pre-commit-config.yaml`).
- External integrations: SMTP email for account creation and password reset (`backend/app/utils.py`), and Sentry for
  error reporting. Production can deploy to FastAPI Cloud (see Deployment).

## Authentication and security
- **OAuth2 password flow with JWT bearer tokens**: login in `backend/app/api/routes/login.py`; tokens signed with HS256 in
  `backend/app/core/security.py`, long-lived access tokens (expiry configured in `backend/app/core/config.py`); current user
  and superuser checks as FastAPI dependencies in `backend/app/api/deps.py`.
- **Password hashing** with pwdlib using Argon2, with bcrypt kept for verifying older hashes (`backend/app/core/security.py`).
- Password reset by emailed, time-limited token (`backend/app/api/routes/login.py`, `backend/app/utils.py`).
- **Authorisation**: active-user and superuser checks only; no roles or per-object permissions beyond item ownership
  (`backend/app/api/routes/items.py`).
- **Configuration and secrets**: all settings from environment variables via pydantic-settings (`backend/app/core/config.py`);
  local values in a committed `.env` (contents not read for this map). The settings class refuses default placeholder
  secrets outside local development. CORS origins are configured in `backend/app/main.py`.
- **Supply chain**: Dependabot (`.github/dependabot.yml`), a dependency guard workflow (`.github/workflows/guard-dependencies.yml`),
  GitHub Actions linting with zizmor (`.github/workflows/zizmor.yml`), and pre-commit checks (`.pre-commit-config.yaml`).
- Frontend auth: token kept client-side and attached by the generated client (`frontend/src/client/core/auth.gen.ts`).

## CI/CD pipeline
All pipelines are GitHub Actions in `.github/workflows/` (actions pinned to commit SHAs):
- Tests: `.github/workflows/test-backend.yml` (Postgres via Docker Compose, migrations, pytest with a coverage gate),
  `.github/workflows/playwright.yml` (builds the stack, runs sharded end-to-end tests),
  `.github/workflows/test-docker-compose.yml` (stack starts and serves).
- Quality: `.github/workflows/pre-commit.yml` (ruff, mypy, ty, biome, typos, client generation), `.github/workflows/zizmor.yml`,
  `.github/workflows/guard-dependencies.yml`, `.github/workflows/smokeshow.yml` (publishes coverage).
- Release and deployment: `.github/workflows/prepare-release.yml`, `.github/workflows/create-draft-release.yml`,
  `.github/workflows/deploy.yml`, `.github/workflows/deploy-docker-compose.yml`.
- Repository housekeeping: `.github/workflows/add-to-project.yml`, `.github/workflows/issue-manager.yml`,
  `.github/workflows/detect-conflicts.yml`, `.github/workflows/bump-pre-commit-hooks.yml`; dependency updates by `.github/dependabot.yml`.

## Deployment and infrastructure
- Two deployment paths, both skipped for the template repository itself:
  - **FastAPI Cloud** on every push to `master` (`.github/workflows/deploy.yml`): builds the frontend, runs
    `backend/scripts/prestart.sh` against the production database, then deploys.
  - **Docker Compose on a self-hosted runner**, triggered manually (`.github/workflows/deploy-docker-compose.yml`):
    builds images, runs the prestart script, then starts `compose.yml` with `compose.deploy.yml`.
- `compose.deploy.yml` adds restart policies, HTTPS routing in Traefik and Let's Encrypt certificates (TLS challenge);
  `compose.override.yml` adds local development settings, mailpit and the Playwright service.
- Images: `backend/Dockerfile` (uv-based Python image); `frontend/Dockerfile.playwright` for tests.
- Configuration per environment through environment variables (`.env` locally, workflow secrets in CI). No IaC
  (Terraform, Kubernetes, Helm) in this repository: none found after checking the inventory and the root folders.
- Database backups and replication: none found in this repository (checked `compose.yml`, `compose.deploy.yml`, workflows).

## Observability
- **Sentry** error reporting and tracing, enabled when a DSN is configured (`backend/app/main.py`, `backend/app/core/config.py`).
- Health check endpoint in `backend/app/api/routes/utils.py`, used by the Compose healthcheck (`compose.yml`).
- No metrics, tracing backend or structured logging configured beyond defaults: none found.

## Testing
- Backend: **pytest** in `backend/tests/` (API routes, CRUD, scripts), shared fixtures in `backend/tests/conftest.py` using one
  session-scoped database; run by `.github/workflows/test-backend.yml` with a coverage threshold.
- Frontend end-to-end: **Playwright** specs in `frontend/tests/` (login, sign-up, items, admin, settings, password reset),
  authenticated setup in `frontend/tests/auth.setup.ts`, run in Compose by `.github/workflows/playwright.yml`.
- Tests run against real PostgreSQL in Docker, not SQLite.

## Dependencies
- Backend (`backend/pyproject.toml`): FastAPI, SQLModel, Alembic, Pydantic and pydantic-settings, PyJWT, pwdlib (Argon2,
  bcrypt), psycopg, emails and Jinja2 for email, sentry-sdk, tenacity (database wait on startup).
- Frontend (`frontend/package.json`): React, TanStack Router/Query/Table, Radix UI with Tailwind CSS, react-hook-form with zod,
  axios; dev tooling Vite, TypeScript, Biome, Playwright, openapi-ts.
- Workspace and tooling: root `pyproject.toml` (uv workspace), root `package.json` (Bun workspaces).

## Conventions
- Python: strict typing with mypy and ty, linting and formatting with ruff (`backend/pyproject.toml`); TypeScript: Biome
  (`frontend/biome.json`).
- All enforced in pre-commit (`.pre-commit-config.yaml`) and CI; the generated client must be regenerated when the API changes.
- Backend layering: routes → dependencies → CRUD helpers → models (`backend/app/api/`, `backend/app/crud.py`, `backend/app/models.py`).

## Hot spots and risks (INTERNAL — never publish)
- Migrations run inside `backend/scripts/prestart.sh` before each start and in the deploy workflows; with several backend
  instances this can race, and it couples every deploy to schema changes.
- A previous migration rewrote primary keys in place (`backend/app/alembic/versions/d98dd8ec85a3_edit_replace_id_integers_in_all_models_.py`).
- Item listing uses offset pagination and a full count per request (`backend/app/api/routes/items.py`); indexes beyond primary
  keys are not defined in `backend/app/models.py`.
- Tests share one database for the session without per-test isolation (`backend/tests/conftest.py`).
- No database backups, replication or connection pooling configured in this repository (`compose.deploy.yml`).
- Long-lived access tokens with no revocation mechanism (`backend/app/core/security.py`); authorisation is limited to
  superuser and ownership checks (`backend/app/api/deps.py`).
- A `.env` file is committed (`.env`); it holds local development defaults, and the settings refuse placeholder secrets
  outside local, but real secrets must never be added to it.
